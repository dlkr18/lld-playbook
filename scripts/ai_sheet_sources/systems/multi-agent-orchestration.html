05 — Deep Dive: Hierarchical Teams

A manager agent breaks the goal into parts and delegates each to a sub-team, which may have its own lead (for example, a research crew of a searcher and a summarizer).

  • Scales to broad tasks without one agent holding every tool and instruction.
  • Each level adds latency, cost and a place for context to be lost in the handoff.
  • Keep depth at two levels or fewer, so a failure can still be traced to one agent.

In CrewAI this is Process.hierarchical; in LangGraph, a supervisor node routing to subgraphs.

06 — Deep Dive: Peer Handoff

Agent handoff with context summary packet passed between peers

Agent A summarizes scratchpad → handoff packet → Agent B continues. OpenAI Agents SDK handoff pattern.

07 — Deep Dive: Blackboard State

Instead of agents passing long messages to each other, all of them read from and write to one shared, structured state: the blackboard.

  • Typical fields: the goal, the plan, findings, the current draft, open questions, and metadata such as call counts.
  • Stored in Redis or Postgres, or as a typed LangGraph state, so it survives restarts and can be inspected.
  • Writes are versioned, so you can see which agent changed what and roll back a bad step.
  • It is the single source of truth: agents never rely on what another agent "said" earlier.

08 — Deep Dive: Termination

Multi-agent systems loop easily, so every run needs several independent stop conditions. Stop when any one fires:

  • The supervisor emits an explicit FINISH once the goal is met.
  • A cap on total agent calls, for example 15 per run.
  • A wall-clock timeout, for example 60 seconds.
  • A cost budget, for example $0.50 per query.

When a cap fires, return the best partial result and say what is missing, rather than failing silently.

11 — Common Pitfalls

  • Multi-agent for single-tool tasks
  • Unbounded supervisor loops
  • No handoff summary — context overflow
  • Agents with identical tool sets (waste)

12 — Interview Q&A

When one agent vs multi-agent?
Start single agent with 3–5 tools. Multi-agent when distinct roles (research/write/code) and parallelizable subtasks justify 2–3× cost.
Explain supervisor pattern.
Supervisor LLM routes to worker agents with specialized prompts/tools. Reads shared state; decides next worker or FINISH.
How prevent infinite agent loops?
max_iterations, wall timeout, cost cap, supervisor must justify each routing decision in trace.
Handoff without losing context?
Structured handoff packet: goal, findings summary, open questions, artifacts. Not raw message history.
Blackboard vs message passing?
Blackboard: shared state all read. Message passing: direct agent-to-agent. LangGraph combines both via StateGraph.
CrewAI vs LangGraph?
CrewAI: role-based crews, faster prototype. LangGraph: explicit state machine, better production control and HITL.
Parallel vs sequential agents?
Parallel when subtasks independent (research 3 sources). Sequential when output feeds next (research → write).
How debug multi-agent failures?
Per-agent trace with inputs/outputs. Replay blackboard state at failure step. Golden trajectories for regression.
Cost control?
Cap LLM calls per agent role. Cache research results. Smaller model for supervisor routing.
Security across agents?
Each agent gets least-privilege tool allowlist. Supervisor cannot execute tools directly.
Human-in-the-loop placement?
Approve before writer sends email; approve supervisor plan for high-risk tasks.
SDE3: design multi-agent support bot?
Supervisor + Research (RAG) + Action (ticket API) agents. Blackboard in Redis. HITL on ticket create. Max 12 LLM calls. Fallback to single-agent on timeout.
