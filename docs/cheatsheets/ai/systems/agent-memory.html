Agent Memory // Systems

Short-term scratchpad, long-term vector store, episodic summaries, and consolidation. Agents need memory — but unbounded context is not memory.

ScratchpadVector MemoryEpisodicSummarizeTTL

Agent memory layers: in-context scratchpad (current turn), session buffer (summarized history), long-term vector memory (user facts), episodic log (past task outcomes).

01 — What & Why

Agents need prior context across turns and sessions. Memory systems trade recall fidelity vs token cost vs latency.

03 — Architecture

Turn -> Scratchpad -> [if tokens > budget] Summarize -> Long-term store (embed)
Query -> Retrieve relevant memories -> Inject into system prompt

04 — Deep Dive: Scratchpad

Working memory: thoughts, tool JSON, observations. Truncate old observations; keep last 3 tool results full.

05 — Deep Dive: Long-Term Vector Memory

User facts embedded and stored in vector DB; retrieved by query similarity at session start

Mem0, Zep, custom pgvector. Store extracted facts not raw chat. user_id namespace isolation.

06 — Deep Dive: Episodic Memory

Log (task, plan, outcome, success). Retrieve similar past tasks when user asks repeat workflow.

07 — Deep Dive: Consolidation

Session end: LLM extracts durable facts, discards ephemeral tool noise, writes to long-term store

End-of-session job: extract preferences, delete contradictions, TTL on time-sensitive facts.

08 — Deep Dive: Memory Retrieval

At session start: embed user message, search memory top-5, inject as system context. Re-rank by recency × relevance.

09 — Production & Ops

  • Dumping full chat history — context overflow
  • Storing contradictory facts without merge
  • Cross-user memory leakage
  • No TTL on outdated preferences

12 — Interview Q&A

Scratchpad vs long-term memory?
Scratchpad: current task working state in context. Long-term: persisted facts across sessions retrieved by embedding similarity.
When summarize vs retrieve?
Summarize when session exceeds token budget. Retrieve when need specific past facts not in recent buffer.
How extract facts for storage?
LLM extraction prompt at session end: list durable user preferences/facts. Discard tool noise and ephemeral data.
Memory privacy?
Strict user_id namespace. Encrypt at rest. Delete API for GDPR. Never cross-tenant retrieval.
Mem0 vs Zep vs roll-your-own?
Mem0/Zep: managed memory layers. Roll-your-own pgvector if need full control and existing stack.
How handle contradictory memories?
Store timestamp + source. On conflict, prefer newer or ask user. Consolidation job merges duplicates.
Episodic memory use case?
User: 'do what I did last Tuesday' — retrieve similar task trajectory and replay adapted plan.
Token budget for memory injection?
Cap retrieved memories at 500–1000 tokens. Top-5 facts usually sufficient.
Reflexion vs episodic?
Reflexion: critique within same task retry. Episodic: store outcome for future different tasks.
Memory for multi-agent?
Shared blackboard for task state; per-agent private scratchpad. Long-term memory at user level not agent level.
Eval memory quality?
Recall: does agent remember stated preference 10 turns later? Precision: no hallucinated memories injected.
SDE3: memory architecture for support bot?
Session buffer with rolling summary. Vector memory for account prefs. Episodic for resolved ticket patterns. TTL 90 days. GDPR purge API.
