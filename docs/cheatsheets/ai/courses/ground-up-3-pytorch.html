01 — Tensors, shapes, broadcasting

Foundation

  • A tensor has a shape, dtype (float32, bfloat16, int64…) and device (cpu, cuda). Ops between tensors on different devices fail.
  • Broadcasting: align shapes from the right; dims of size 1 stretch. (B, T, D) + (D,) adds a bias to every token.
  • Views vs copies: view, transpose, slicing share memory; .contiguous() or .clone() copy. view needs contiguous memory; reshape copies if it must.
x = torch.randn(8, 128, 768)             # (B, T, D)
h = x.view(8, 128, 12, 64).transpose(1, 2)  # (B, heads, T, head_dim) for attention
scores = h @ h.transpose(-2, -1)         # (B, 12, 128, 128)

02 — Autograd in PyTorch

Foundation

  • Tensors with requires_grad=True (all nn.Parameters) record operations into a dynamic graph.
  • loss.backward() fills .grad on leaf tensors and frees the graph.
  • torch.no_grad() / torch.inference_mode(): no graph, less memory. Always use at eval and inference.
  • .detach(): cut a tensor from the graph (e.g. targets computed from the model itself).
  • .item() forces a GPU→CPU sync; calling it every step slows training.

03 — nn.Module, train/eval, state_dict

Foundation

class MLP(nn.Module):
    def __init__(self, d_in, d_h, d_out):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(d_in, d_h), nn.GELU(),
                                 nn.Dropout(0.1), nn.Linear(d_h, d_out))
    def forward(self, x):            # x: (B, d_in)
return self.net(x)           # (B, d_out) logits

Submodules and nn.Parameters assigned as attributes are registered automatically, so model.parameters(), .to(device) and state_dict() find them. model.train() / model.eval() switch dropout and BatchNorm behavior.

04 — Datasets and DataLoaders

Foundation

class TextDS(torch.utils.data.Dataset):
    def __init__(self, rows, tok): self.rows, self.tok = rows, tok
    def __len__(self): return len(self.rows)
    def __getitem__(self, i): return self.tok(self.rows[i])["input_ids"]

def collate(batch):                              # pad variable lengths
    ids = nn.utils.rnn.pad_sequence([torch.tensor(b) for b in batch],
                                    batch_first=True, padding_value=PAD)
    return ids, (ids != PAD).long()              # input_ids, attention_mask

dl = DataLoader(ds, batch_size=16, shuffle=True, num_workers=4,
                pin_memory=True, collate_fn=collate)

Low GPU utilization is very often a starving data loader. Pre-tokenize, use workers, and pin memory.

05 — A complete, trustworthy training loop

Core

model = Model().cuda()
opt = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.1, betas=(0.9, 0.95))
total = epochs * len(dl) // accum
sched = get_cosine_schedule_with_warmup(opt, int(0.03 * total), total)

step = 0
for epoch in range(epochs):
    model.train()
    for i, (x, y) in enumerate(dl):
        x, y = x.cuda(non_blocking=True), y.cuda(non_blocking=True)
        with torch.autocast("cuda", dtype=torch.bfloat16):
            loss = F.cross_entropy(model(x), y) / accum
        loss.backward()
        if (i + 1) % accum == 0:
            gnorm = torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            opt.step(); sched.step(); opt.zero_grad(set_to_none=True)
            step += 1
if step % 50 == 0: log(loss.item() * accum, gnorm, sched.get_last_lr())
            if step % 1000 == 0: save_ckpt(model, opt, sched, step)
    evaluate(model, val_dl)          # model.eval() + torch.no_grad() inside

06 — Mixed precision: fp32, fp16, bf16, fp8

Core

FormatBits (exp/mantissa)RangeNotes

bf168 / 7±3e38Same range as fp32; default on Ampere+

Autocast runs matmuls in low precision (tensor cores, ~2× faster, half the activation memory) while keeping sensitive ops like softmax and reductions in fp32.

07 — Where GPU memory goes

Core

full training, mixed precision, AdamW, per parameter:
  bf16 weights 2 + bf16 grads 2 + fp32 master 4 + Adam m,v 8 = 16 bytes
+ activations ∝ batch × seq_len × width × layers
inference: bf16 weights 2 bytes/param (+ KV cache for LLMs)

Lab: how much GPU memory will this need?

OOM toolbox, in order of least pain: smaller micro-batch + gradient accumulation, shorter sequences, bf16, activation checkpointing, 8-bit optimizer, LoRA/QLoRA, FSDP across GPUs.

08 — Activation (gradient) checkpointing

Core

Instead of storing every layer's activations for backward, store only the layer inputs, then recompute the inside of each layer during backward. Costs ~30% more compute, often cuts activation memory 5–10×. One flag in HF: model.gradient_checkpointing_enable().

09 — torch.compile and profiling

Advanced

torch.compile(model) traces the model and generates fused kernels (via TorchInductor/Triton), removing Python overhead and memory round-trips. Typical 1.3–2× speedups; first call is slow (compiling); dynamic shapes can trigger recompiles.

Profile before optimizing: torch.profiler shows time per op and whether the GPU idles waiting on the CPU or data loader.

10 — Debugging a training run

Core

  1. Check initial loss. Classification over K classes should start near ln K. Far above it means bad init or a bug.
  2. Overfit one batch. Loss on a single fixed batch must go to ~0. If it can't, the model or loss is broken, not the data.
  3. Print shapes and a decoded sample of inputs and labels right before the model. Off-by-one in labels for LMs is common.
  4. Watch gradient norm. Spikes precede divergence; NaN means overflow or log(0).
  5. LR range test: sweep LR exponentially for a few hundred steps, pick a bit below where loss explodes.
  6. Then scale up data and model.

11 — Check yourself

Batch 8, accumulation 4, 2 GPUs: effective batch?
64.
Why divide the loss by the accumulation steps?
Gradients sum across backward calls; dividing makes the accumulated gradient equal the average over the effective batch, so LR means the same thing.
Memory to fully fine-tune a 7B model with AdamW?
~16 B/param → ~112 GB plus activations: needs multiple 80 GB GPUs or sharding.
Your model can't overfit a single batch. What now?
Bug hunt: labels misaligned, loss on wrong tensor, LR zero or huge, model frozen (requires_grad False), masking everything out.
