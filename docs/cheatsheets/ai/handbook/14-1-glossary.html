01 — 97 terms

TermMeaning
TokenWord-fragment; the unit models read/write and bill by (~4 chars).
Context windowMax tokens a model can consider at once (system+history+retrieved+output).
PromptThe text you send the model; system prompt sets persistent role/rules.
AutoregressiveGenerating one token at a time, each conditioned on all prior tokens.
TransformerThe neural-net architecture behind LLMs; core mechanism is attention.
AttentionLets each token weigh every other token to decide relevance.
Parameters / weightsThe billions of learned numbers that make up the model.
Pre-trainingFirst stage: learn language by predicting next tokens on huge corpora.
SFTSupervised fine-tuning on (instruction→answer) pairs; teaches request-following.
RLHF / DPOAlignment from human preferences; makes models helpful/safe.
TemperatureRandomness in decoding; 0 = deterministic, higher = creative.
max_tokensHard cap on output length (and cost).
HallucinationConfident, fluent, wrong output; fix with RAG + verification.
Knowledge cutoffThe date past which the model knows nothing; fix with tools/RAG.
Embedding / vectorText encoded as numbers where similar meaning = close.
Cosine similarityAngle-based measure of how close two vectors are.
Vector databaseStores vectors; finds nearest-by-meaning fast.
ANN / HNSWApproximate nearest-neighbor index; fast vector search at scale.
Top-K / over-fetchRetrieve K (or more, then rerank down) nearest matches.
Payload / metadata filterRecord metadata; constrain search by it (lang, date, user).
ChunkingSplitting documents into overlapping pieces before embedding.
RerankingCross-encoder reorders retrieved candidates; biggest RAG quality lever.
Hybrid searchFuse vector similarity with keyword/BM25 search.
RAGRetrieve real data → put in prompt → generate grounded answer.
Recall@kEval: is the correct chunk in the top-k retrieved?
FaithfulnessEval: is the answer actually supported by the sources?
Tool / function callingThe model requests a function; your code runs it.
tool_use / tool_callsThe block the model emits to request a call (name+input+id).
tool_resultYour reply with the function output, keyed by id; must be a string.
tool_choiceauto | any | {name} | none — controls whether/which tool is called.
is_errorFlag telling the model a tool call failed so it can recover.
MCPModel Context Protocol — open standard for exposing tools/data to agents.
AgentLLM + goal + tools + a loop that runs until done.
WorkflowHard-coded steps; the LLM fills in blanks (vs agent control flow).
Harness / runtimeThe code running the loop, tools, budgets, retries.
ReActInterleave reasoning and tool actions each step.
ReflectionSelf-critique and revise; basis of evaluator-optimizer.
Plan-and-executePlan fully, then execute, re-planning as needed.
Orchestrator–workersManager decomposes a task, workers do pieces, manager synthesizes.
RoutingClassifier sends input to a specialized branch/model.
Voting / consensusRun a task N times, take the majority (reliability).
Budget / max_stepsHard cap on steps/tokens/time/spend; prevents runaway loops.
Working memoryThe messages list in the current window.
Episodic memoryPast interactions in a vector store, retrieved when relevant.
Semantic memoryFacts/knowledge accessed via RAG.
Procedural memorySkills/routines encoded in the system prompt.
External memoryFiles/DB the agent writes and re-reads (survives compaction).
Context engineeringDeciding what goes in the window each turn — the production skill.
CompactionSummarizing old turns to free context while preserving key facts.
Prompt cachingReuse a stable prompt prefix → ~90% cheaper input tokens.
HandoffTransferring control (and history) from one agent to another.
Sub-agentAgent run as a tool in a fresh context; returns a distilled result.
LLM-as-judgeUsing a model to score outputs on a rubric (must be calibrated).
Trajectory evalChecking the agent steps/tool-use were sane, not just the answer.
TracingLogging every model/tool call: prompt, tokens, cost, latency, decision.
Backoff + jitterExponential retry delay + randomness on rate limits/flaky calls.
IdempotencyA side-effecting action safe to retry without duplicating it.
Circuit breakerStop calling a failing dependency after repeated errors.
Prompt injectionUntrusted content carrying instructions that hijack the agent.
Least privilegeScoped, minimal tool permissions to limit blast radius.
Excessive agencyAn over-empowered agent taking consequential actions when manipulated.
Model routing / cascadeCheap model for easy steps, strong model for hard/verify.
Durable executionCheckpointed long-running jobs that resume after crashes (Temporal/LangGraph).
Fine-tuning / LoRAExtra training to change behavior/style; LoRA = cheap low-rank adapter.
Structured outputForcing JSON/typed results for programmatic use.
Gradient descentθ ← θ − η·∇L: step downhill on the loss; how all training works.
BackpropagationChain rule through the computation graph; computes the gradients.
Cross-entropy−Σ y·log p — the next-token training loss.
SoftmaxTurns scores into probabilities that sum to 1.
BPEByte-pair encoding — merge frequent pairs to build the token vocabulary.
Q / K / VQuery, key, value projections; attention = softmax(QKᵀ/√dk)·V.
Residual connectionAdd input to output; makes deep stacks trainable.
Bias vs varianceUnderfit (both bad) vs overfit (train good, val bad).
Data leakageFeature/eval contains info unavailable at prediction time → fake wins.
CalibrationDo 0.7-confidence predictions come true ~70% of the time?
SFTSupervised fine-tuning on (instruction → answer) demonstrations.
QLoRALoRA on a 4-bit-quantized base — fine-tune big models on one GPU.
Reward modelScores (prompt, answer) with a scalar; trained on preference pairs.
RLHFSFT → reward model → RL (PPO) with a KL leash to the reference model.
DPODirect preference optimization — RLHF outcome via a supervised loss, no RL.
KTO / IPO / ORPODPO variants: thumbs-only data / bounded loss / folded into SFT.
Reward hackingPolicy exploits the imperfect reward proxy; Goodhart industrialized.
RLVRRL from verifiable rewards (tests/answers pass) — trains reasoning models.
KL divergenceDistance between distributions; the leash in RLHF/DPO.
Prefill vs decodeParallel prompt processing (TTFT) vs token-by-token generation.
KV cacheStored keys/values per token; 2·layers·tokens·kv_heads·head_dim·bytes; caps concurrency.
PagedAttentionVirtual-memory-style KV allocation (vLLM) — no fragmentation, shared prefixes.
Continuous batchingAdmit/evict requests mid-generation; the big throughput win.
TTFT / TPOTTime to first token / time per output token.
QuantizationLower-precision weights (int8/int4) — memory & speed for some quality.
Speculative decodingDraft model proposes tokens; target model verifies in one pass.
VAD / endpointingDetecting speech / deciding the speaker finished (voice agents).
Barge-inUser talks over the bot → cancel TTS + generation instantly.
STT / TTSSpeech-to-text / text-to-speech; the voice agent’s I/O layer.
DriftInput/prediction distributions moving away from training data.
Training-serving skewPreprocessing differs between training and serving.
Canary / shadowSmall-% rollout / run silently beside prod before shipping.
