Talking to a model: the API call // 2.3

Forget the chat UI. Under it is a simple HTTP call. Here's exactly what you send and get back.

Part 2 · LLM foundationsChapter 2.3

01 — The mental model: a list of messages

You send a list of messages, each with a role. The model returns the next assistant message. There are three roles:

  • system — your standing instructions (who the model should be, rules, format). Set once.
  • user — what the human says.
  • assistant — what the model said (you include past ones to give it memory of the conversation).

Under the SDK it's literally one HTTPS POST: a JSON body with model, messages, and limits, an API-key header, and a JSON response containing the assistant message plus a usage object telling you what you'll be billed. Everything else in this book — RAG, tools, agents — is decoration on this one call.

first_call.py — the complete, runnable Anthropic versionpython
import anthropic

client = anthropic.Anthropic()                  # reads ANTHROPIC_API_KEY from env

resp = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=300,                             # cap on the OUTPUT length
    system="You are a concise assistant. Answer in one sentence.",
    messages=[
        {"role": "user", "content": "What is a vector database?"}
    ],
)
print(resp.content[0].text)
print(resp.usage)        # → input_tokens=…, output_tokens=…  (this is your bill)
print(resp.stop_reason)  # → "end_turn" (finished naturally) or "max_tokens" (truncated!)

The same call against OpenAI — note what moves around. The shape is 95% identical; the differences below are the entire porting cost:

first_call_openai.py — the complete, runnable OpenAI versionpython
from openai import OpenAI

client = OpenAI()                               # reads OPENAI_API_KEY from env

resp = client.chat.completions.create(
    model="gpt-4o",
    max_tokens=300,
    messages=[
        # system is just another message here, not a separate parameter:
        {"role": "system", "content": "You are a concise assistant. Answer in one sentence."},
        {"role": "user",   "content": "What is a vector database?"},
    ],
)
print(resp.choices[0].message.content)          # content path differs from Anthropic
print(resp.usage)          # → prompt_tokens=…, completion_tokens=…  (names differ too)
print(resp.choices[0].finish_reason)            # "stop" or "length" (= truncated)

OpenAI looks the same

OpenAI's API uses the same messages+roles shape (client.chat.completions.create). The system role, the message list, the usage object — all analogous. Learn one, read them all. (Nearly every other provider — Google, Mistral, local servers like vLLM and Ollama — exposes an OpenAI-compatible endpoint, so this shape is effectively the industry's lingua franca.)

02 — Holding a conversation = resending history

The API is stateless — it remembers nothing between calls. "Memory" is an illusion you create by resending the whole message list each time, with the new turn appended.

multi_turn.py — memory is you, resending everythingpython
M = "claude-sonnet-4-5"
messages = [{"role": "user", "content": "My name is Sam."}]
r1 = client.messages.create(model=M, max_tokens=100, messages=messages)
messages.append({"role": "assistant", "content": r1.content[0].text})  # keep its reply
messages.append({"role": "user", "content": "What's my name?"})        # add new turn
r2 = client.messages.create(model=M, max_tokens=100, messages=messages)  # "Sam" ✓

In a real app you'll want that bookkeeping — plus token accounting so you can see costs grow — wrapped in one place. Here's a small conversation class you can actually ship a prototype on:

conversation.py — multi-turn wrapper with token & cost trackingpython
import anthropic

class Conversation:
    """Owns the message list; tracks tokens and (illustrative) cost per session."""
# Illustrative prices — always check your provider's current price sheet.
    PRICE_IN_PER_MTOK = 3.00 # $ per million input tokens
    PRICE_OUT_PER_MTOK = 15.00 # $ per million output tokens
def __init__(self, system: str, model: str = "claude-sonnet-4-5"):
        self.client = anthropic.Anthropic()
        self.model, self.system = model, system
        self.messages: list[dict] = []
        self.total_in = self.total_out = 0
def say(self, user_text: str, max_tokens: int = 500) -> str:
        self.messages.append({"role": "user", "content": user_text})
        resp = self.client.messages.create(
            model=self.model, system=self.system,
            max_tokens=max_tokens, messages=self.messages,
        )
        if resp.stop_reason == "max_tokens":
            # Truncated mid-thought — surface it instead of silently storing half an answer.
print("[warn] reply truncated; raise max_tokens or ask for shorter output")
        text = resp.content[0].text
        self.messages.append({"role": "assistant", "content": text})
        self.total_in += resp.usage.input_tokens
        self.total_out += resp.usage.output_tokens
        return text

    @property
def cost(self) -> float:
        return (self.total_in * self.PRICE_IN_PER_MTOK
                + self.total_out * self.PRICE_OUT_PER_MTOK) / 1_000_000

chat = Conversation(system="You are a terse senior engineer.")
print(chat.say("My name is Sam. Remember it."))
print(chat.say("What's my name?"))                      # → mentions Sam
print(f"turns={len(chat.messages)//2} in={chat.total_in} "
f"out={chat.total_out} cost=${chat.cost:.4f}")

Run that and watch input_tokens climb turn over turn even though each user message is tiny — turn 2's input includes turn 1's question and answer. Worked numbers (illustrative): if the system prompt is 40 tokens and each turn adds ~120 tokens of history, turn 1 costs ~60 input tokens, turn 10 costs ~1,150, and turn 50 costs ~5,900 — a two-orders-of-magnitude drift you'll never notice in a demo and will absolutely notice on the invoice.

03 — Streaming: tokens as they're generated

By default you wait for the whole response. For anything user-facing, request a stream instead: the API sends tokens as they're produced, so the user sees output in ~1 second instead of staring at a spinner for 20. Same request, one flag, an iterator instead of an object:

streaming.py — print tokens as they arrive (both SDKs)python
# Anthropic
with client.messages.stream(
    model="claude-sonnet-4-5", max_tokens=500,
    messages=[{"role": "user", "content": "Explain DNS in 3 paragraphs."}],
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
final = stream.get_final_message()       # full message + usage, after the stream ends
print(f"\n[{final.usage.output_tokens} tokens]")

# OpenAI
stream = openai_client.chat.completions.create(
    model="gpt-4o", max_tokens=500, stream=True,
    messages=[{"role": "user", "content": "Explain DNS in 3 paragraphs."}],
)
for chunk in stream:
    delta = chunk.choices[0].delta.content
    if delta:
        print(delta, end="", flush=True)

Streaming changes perceived latency, not total latency or cost. The metric to watch is time-to-first-token (typically well under a second) versus total generation time (potentially tens of seconds for long outputs).

04 — When the call fails (it will)

Production code talks to a rate-limited, occasionally overloaded remote service. You will see these shapes; know them before they page you:

HTTPMeaningWhat you do
400 invalid_request_errorYour JSON is wrong: bad role, context window exceeded, missing max_tokensFix the request — retrying is pointless
401 authentication_errorBad/missing API keyCheck env var and key rotation — don't retry
429 rate_limit_errorToo many requests/tokens per minuteBack off exponentially, respect retry-after header
500/529 api_error / overloaded_errorProvider-side troubleRetry with backoff + jitter; fail over if persistent

A 429 body looks like this — worth recognizing on sight:

error_shapes — what comes back when it goes wrongjson
// HTTP 429, with a retry-after header
{"type": "error",
 "error": {"type": "rate_limit_error",
           "message": "Number of request tokens has exceeded your per-minute rate limit"}}

// HTTP 400 — the classic beginner one: prompt too big for the window
{"type": "error",
 "error": {"type": "invalid_request_error",
           "message": "prompt is too long: 214341 tokens > 200000 maximum"}}
retry.py — minimal retry-with-backoff around a callpython
import time, random, anthropic

def call_with_retry(client, max_retries=4, **kwargs):
    for attempt in range(max_retries + 1):
        try:
            return client.messages.create(**kwargs)
        except (anthropic.RateLimitError, anthropic.APIStatusError) as e:
            retryable = isinstance(e, anthropic.RateLimitError) or e.status_code >= 500
if not retryable or attempt == max_retries:
                raise # 400/401 or out of budget: surface it
            delay = min(2 ** attempt + random.random(), 30)   # 1s, 2s, 4s… + jitter
            time.sleep(delay)
# Note: the official SDKs already retry 429/5xx a couple of times internally —
# configure via anthropic.Anthropic(max_retries=…) — but you still need to handle
# the final failure and log it.

Mini-scenario: the demo that died on launch day

You build a support-bot demo: one user, works flawlessly. Launch day, 40 concurrent users, and three things happen inside an hour. First, 429s — you never handled them, so users see stack traces (fix: the retry wrapper above, plus a queue). Second, a power user pastes a 300-page PDF; the request dies with the prompt is too long 400 (fix: count tokens before sending, chunk or refuse). Third, finance asks why yesterday cost $60 when your estimate was $5 — you forgot that resending history multiplies input tokens per turn (fix: log resp.usage per call from day one, alert on daily spend). None of these are exotic; all three are visible in this chapter's code before you ever ship.

Beginner gotchas

  • Forgot to append history? Total amnesia every call. Forgot to append the assistant's reply (only appending user turns)? Subtler amnesia — the model contradicts what it said a minute ago.
  • Long conversations cost more every turn (you resend everything). This is exactly why "context management" (Part 6) becomes a real engineering problem.
  • Check stop_reason. max_tokens means the answer was cut mid-sentence; storing it as if complete corrupts the conversation and any JSON you were parsing.
  • Never hardcode the API key. Environment variables or a secrets manager; keys in git are harvested by bots within minutes of a public push.
  • Set timeouts. A hung HTTPS connection with no client timeout is a stuck worker; SDKs accept a timeout= parameter — use it.

Takeaways

  • One POST: model + message list in, one assistant message + usage out.
  • The API is stateless; memory = you resending history, and paying for it each turn.
  • Anthropic and OpenAI differ only in surface details (system placement, field names); the mental model transfers everywhere.
  • Stream for humans, check stop_reason, retry 429/5xx with backoff, log usage from day one.
